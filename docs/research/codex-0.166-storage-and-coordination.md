### Exact source facts

* **Stable thread UUID is not immutable rollout UUID.** Revert keeps thread identity while selecting a new rollout. Canonical filename is `rollout-<timestamp>-<threadUUID>.jsonl[.zst]` or `<threadUUID>_<rolloutUUID>` after revert. SessionMeta.id supplies owning thread; history_base points at a rollout segment with ordinal/byte cutoff, and can include self-revert lineage. [Filename parser](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/rollout/src/rollout_file_name.rs#L10-L62), [selected-rollout resolver](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/thread-store/src/local/thread_rollout_resolver.rs#L1-L121).
* Resolver order is live writer, SQLite selected path, then legacy filesystem fallback (active/optionally archived). For a known paginated row, missing selected path does **not** authorize choosing an older segment. Persistent DB error propagates from the requery. A path or filename UUID alone is not full ownership/selected-history proof. Same resolver link above.
* Paginated model replay consumes bounded immutable lineage segments and may stop at latest complete compaction; legacy retains full-history path. It validates first SessionMeta against requested thread. A copied fork can be independent; a reference-backed fork can require source segments owned by another stable thread. [Model context](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/thread-store/src/local/model_context.rs#L26-L110), [lineage resolution](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/thread-store/src/local/rollout_lineage.rs#L26-L41).

## Locking: concrete coverage and limits

| Mechanism | Exact source observation | Implication for scoped research |
|---|---|---|
| `$CODEX_HOME/thread-writer-locks/<canonicalUUID>.lock` and `.coordination.lock` | Writer acquisition holds global coordination while opening/locking per-thread file; active lock returns WouldBlock. Global wait is bounded 30s with 50ms polls. Guard holds file until owner finishes, cleanup coordinated. [writer_lock.rs](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/rollout/src/writer_lock.rs#L19-L137) | Real cross-process primitive exists. File existence/age is not ownership; do not delete/recreate lock inode, infer dead owner, steal, or call absent lock proof of inactivity. |

[live_writer.rs](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/thread-store/src/local/live_writer.rs#L26-L84) | Loaded-but-idle can still own writer; stopped UI turn is not lock release. | Reference-backed fork preparation | Keeps in-process source reservation until prepared fork is consumed/dropped; resolution/reference materialization uses store-local writer coordination. | `.tmp/rollout-maintenance.lock` | Shared compression/migration exclusive advisory file lock; nonblocking acquisition. | `session_index.jsonl.lock` | Append/rewrite use permanent separate lock inode, 30s bound. Replacing lock file splits coordination; preserve its identity. |

The original merged [single-writer PR #34986](https://github.com/openai/codex/pull/34986) explicitly intends one writable app-server while other processes can read. It is not an offline global cleanup protocol. Exact source also updates paginated SQLite metadata/name index without the same OS writer-lock branch, while attachments use in-process lifecycle reservations plus SQLite. [metadata branch](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/thread-store/src/local/update_thread_metadata.rs#L107-L176), [attachments](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/thread-store/src/local/thread_attachments.rs#L17-L101). **Inference:** holding target writer lock alone is not established as fencing all logical metadata, new references, shared stores or external/noncooperating clients. Multi-store complete quiescence still needs an explicit reviewed assumption or mechanism.

## Native deletion semantics and shared-history boundary

[App Server delete](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/app-server/src/request_processors/thread_delete.rs#L31-L72) computes spawn subtree, validates root, checks attached children, prepares each local loaded thread for removal, and calls store batch delete descendants before root. Its one UUID request is **not** a target-only command. [Subtree calculation](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/core/src/thread_manager.rs#L1145-L1183) unions persisted spawn descendants and that manager's live runtime descendants. It does not union every unrelated process's registry.

Store deletion locks sorted/deduplicated stable target IDs, acquires OS ownership before cleanup, scans active and archived metadata reference graph, rejects attached children/external history references, runs host cleanup, removes per-rollout projected histories, discards queued recorder work, removes plain+zstd variants, removes name entries, then final state cleanup. It keeps main retry graph until all rollouts succeed. [delete_thread.rs](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/thread-store/src/local/delete_thread.rs#L123-L166), [history/file/name order](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/thread-store/src/local/delete_thread.rs#L231-L314).

**Reference scan limitations:** `RolloutReferenceIndex` keys immutable rollout IDs, identifies owner from SessionMeta, tracks history_base references and attached-child parent. Missing roots are skipped, directory errors propagate, unreadable/malformed metadata is skipped, and duplicate rollout IDs keep first encountered entry. Filtered scans explicitly disclaim sufficient reference counts for deletion. [index implementation](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/rollout/src/rollout_reference_index.rs#L19-L153). Thus duplicating this internal helper would not by itself give AgentMender's stricter complete negative proof under corruption/ambiguous aliases.

## Storage surfaces and functional consequences

| Surface | Exact evidence | Boundary |
|---|---|---|
| All owned immutable JSONL segments, active/archived, plain/compressed | File parser + deletion above | A stable thread can own several segments; shared segments may serve retained forks. Removing filename match alone can break unrelated history. |
| `thread_history_1.sqlite` | Deletes thread_items, thread_realtime_items, thread_turns, projection_state in one BEGIN IMMEDIATE, keyed by rollout identity passed by caller. [projection deletion](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/thread-store/src/local/thread_history.rs#L242-L283) | Main state row is not sole content store. Deleting projection alone permits rematerialization from replay inputs. Separate SQLite transaction from state DB. |
| `state_5.sqlite` and runtime stores | logs, queue, all existing memory versions and goals are removed before main state's dynamic-tools/edges/read-receipts/thread rows transaction. [state cleanup](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/state/src/runtime/threads.rs#L1183-L1244), [memory versions](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/state/src/runtime/memory_versions.rs#L39-L53) | No cross-database/filesystem atomic commit. FK cascades and shared links must be audited, not assumed contained by WHERE id. |
| Configured SQLite homes | Filenames state_5/logs_2/goals_1/memories_1/queue_1/thread_history_1; memories_v2 lazy; logs may have separate local home. [SQLite configuration](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/state/src/sqlite.rs#L49-L54), [path methods](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/state/src/sqlite.rs#L261-L320) | CODEX_HOME assumptions alone do not locate every configured store. WAL/SHM/journals are database coordination, not per-thread disposable files. |
| Live recorder + queued writes | Source holds writer ownership and discards queued recorder before removal | Without fencing, unlink may leave open bytes usable/writable or state recreated; neither UI closed nor last task_complete proves owner gone. |
| Host message boards | Core supplies thread-data-cleanup callback deleting local boards before rollout removal. [composition](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/core/src/thread_manager.rs#L528-L559) | Additional host-specific effects. Native helper itself admits host composition, so thread-store core is not universal closure. |
| Name index, Desktop catalog, plugin stores | Name index is native source. Desktop catalog/plugin behavior below is issue evidence, not exact open-source release contract. | Functional absence, UI disappearance, full cleanup, and physical space reclamation are distinct promises. |

**No verified minimal destructive cut set is claimed.** Source supports why removing only main DB row, only rollout, or only projected rows is insufficient for complete local deletion: fallback/replay/materialization/live/host views differ. A deliberately narrower operation would need to define its observable local functional postcondition and retained dependency policy; shared history cannot be removed merely to make target inaccessible. Finite filesystem absence cannot establish all views or secure erasure. M8.1's blockers remain historically accurate.
