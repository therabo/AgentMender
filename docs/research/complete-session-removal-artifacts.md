## Status semantics

The following statuses describe current compiled scoped-cleanup-v1 behavior, not claimed M8.2.1 completion: Removed means included in the accepted M8.2 exact-primary cut; Unsupported means no approved production mutation/profile, even where source proves a promising exact record; RetainedShared/Ambiguous/Unknown mean protect. A missing store is absence only within an explicitly observed scope, never global absence. These classes must not disguise required projection residue: Unknown or unsupported projecting state prevents product Removed.

## Required safety changes before promoting any candidate

1. A new reviewed exact profile must declare every path/container/record, schema, app identity/version/root and coordination effect. Do not silently broaden scoped-cleanup-v1 or reinterpret M8.2 receipts as GUI removal.
2. Manifest approval must commit exact record identity/preimage, full physical file identity, all extra DB rows and optional artifacts. Shared container remains; mutation unit is exact approved row/record/subtree. Newly discovered artifacts require replan.
3. Each separate SQLite database needs its own proven exclusion, schema/foreign-key/trigger contract and semantic retained-row digest; main DB exclusive lock cannot fence logs/goals/queue/message board/desktop catalogs. Cross-DB crash ordering must retain exact partial knowledge, never auto-retry unknown effects.
4. Shared JSONL replacement needs bounded strict duplicate-aware parse, preserve untouched raw line bytes and order, private same-directory create-new replacement, fsync, descriptor-relative atomic replacement, parent sync and reopen verification under a proof that all relevant writers are excluded. Existing provider append locks on the old inode alone do not protect a renamed replacement against a writer waiting on the old inode.
5. Optional technical failure can permit residual success only after proven nonprimary/nonprojecting classification. Unknown supported projection risk and missing restart evidence block product success.
6. Coverage must count exact artifact identities and measurable bytes with checked arithmetic. No ownership confidence percentage. Every approved stable safe item must be attempted; a metric cannot authorize scope.
