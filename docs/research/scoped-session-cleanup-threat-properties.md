# Scoped local one-session threat review and generated-property proposal

Research/review only, 2026-10-31. Basis: exact Codex0.166.0 source commit6ff1e1ca3b30fc8b914720681fcf5fe62e95f856 at `/tmp/agentmender-research/openai-codex`, current-stable external verification, and companion `/tmp/agentmender-reconstruction/codex-storage-research.md`. No repository edit, provider execution, real-user effect, production capability or final design is introduced.

## Review conclusion

A narrower operation scoped to one complete canonical stable UUID is a materially different claim from native cascading cleanup or global reclamation. It can be investigated, but neither UUID parsing, a native lock, nor observed source structure alone proves it safe. The proof obligation must be **exact local session effect with retained unrelated behavior/data**, and failures must preserve explicit partial state. Do not call a successful local postcondition provider-global absence, privacy erasure, compensation, or native lifecycle authority.

The exact source establishes useful primitives and counterexamples. OS writer locks exist; in-process lifecycle reservations and loaded registries are separate. Shared immutable history can belong to one stable thread while another depends on it. Thread UUID and rollout UUID differ after revert. Per-table SQL transactions do not make files/multiple DBs atomic. Read/index/projection/native UI views disagree under legitimate migration and failure. These are concrete issues to resolve before eligibility, not reasons to infer no scoped operation could ever be defined.

## Threat assumptions that must be explicit

| Threat | Required position for review |
|---|---|
| Ordinary simultaneous Codex clients: Desktop, CLI, daemon, remote, watcher, migration, compression, background SQLite metadata | Must fence the applicable writers for the complete plan/effect/verification interval or refuse. Target writer lock alone has not been shown to cover all metadata/reference mutation. |
| Partial discovery, unreadable/corrupt SessionMeta, repeated rollout IDs, contradictory native IDs, unsupported layouts | Preserve uncertainty/conflicts; no mutation or completeness assertion. Upstream scan skips unreadable headers/first duplicate; duplicating that behavior does not meet stronger AgentMender proof. |
| Same-user path substitution, symlink/hardlink alias, root relocation, permission/ownership changes | Define concrete supported filesystem/identity validation and immediately revalidate. Path containment once is not future ownership; a shared inode may represent retained unrelated data. |
| Malicious same-user process or privileged writer ignoring advisory locks | OS advisory coordination cannot defeat it. State this as excluded or supply stronger confinement; do not claim cryptographic control over same-user provider state. |
| Unknown/mixed-version/nonlocal provider/home, NFS lock semantics, app-specific external stores | Unsupported until exact tests/contracts. Current runtime supports configurable SQLite/log homes; no fixed-home assumption. |
| Process stop/request disconnect/last task_complete/UI archive/old mtime | None proves no loaded writer. No killing, forced unlock, rewriting native lockfiles or file-age eviction as cleanup prerequisite. |
| Physical reclamation or secure erasure | Excluded from logical session-removal proof: WAL, freelists, APFS clones, snapshots, open deleted handles, backups and cloud/plugin copies differ. |

Additional exact-source trap: WriterLockCoordinator.acquire performs a one-time scan/removal of every stale per-thread lock under coordination, not only the requested UUID. Reusing it unchanged can mutate unrelated lock bookkeeping. Guard drop reacquires coordination before releasing/removing its thread lock. A future primitive must account for those incidental effects and lock ordering; merely holding global coordination while dropping a guard can self-wait. [writer_lock.rs](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/rollout/src/writer_lock.rs#L45-L51), [drop](https://github.com/openai/codex/blob/6ff1e1ca3b30fc8b914720681fcf5fe62e95f856/codex-rs/rollout/src/writer_lock.rs#L182-L210).

## Mathematical properties to specify before implementation

Let S be a coherent bounded provider state with all declared stores and physical identities. T is the canonical128-bit stable session UUID. Keep raw observation spelling separately. Let Own(S,T) be admitted exclusively target-owned logical rows/files, Dep(S,T) the retained-thread dependency relations into target-owned segments, U(S,T) all unrelated declared observable records/bytes/functions, and A the exact independently approved effect set. A must never expand after approval. Successful execution is E(S,T,A)=(S',receipt). Refusal returns S unchanged except narrowly declared owned AgentMender bookkeeping; started/partial execution returns explicit Unknown/RecoveryRequired unless exact complete postcondition is positively proved.

1. **Identity injectivity:** accepted raw UUID aliases canonicalize to all128bits; distinct UUIDs never merge. Preserve original conflicting descriptors before canonical dedup. Reject prefix IDs, whitespace/lossy parsing, path-derived substitute IDs and mismatched filename/header/state ownership. ThreadId and RolloutId are distinct semantic types even when represented by UUID.
2. **One-target non-expansion:** all provider changes are in the typed approved A for T. Spawn/fork/project/cwd/attachment reachability cannot add an unapproved session. If target effect requires a retained dependency's mutation, refuse rather than broaden A.
3. **Noninterference:** project unaffected logical rows into a canonical deterministic representation P_U; require P_U(S')=P_U(S), and byte-for-byte equality for unrelated ordinary files. Also require retained histories' replay/paged output and identity/path selection unchanged. Whole DB byte equality is inappropriate for scoped row changes, but changed SQLite pages cannot excuse unrelated logical changes.
4. **Shared-history preservation:** if a retained U depends on any rollout segment belonging to T, no destructive publication until a reviewed policy proves equivalent retained behavior; initially such dependency must refuse. Copied fork, spawn edge, attached parent and history_base are separate relations; same cwd/name/session tree does not prove physical sharing.
5. **Closure completeness:** every declared target-owned representation (active/archived, selected/older reverted segments, plain/zstd, projections and exact rows) is covered or excluded with an honest promise. Unknown stores/unreadable reference input disable eligibility. Scan page completion or current-view miss does not imply this property.
6. **Freshness:** every identity/ownership/dependency/profile/retained baseline checked during planning must still match under effective exclusion immediately before the first provider effect. Any drift invalidates A/approval; hash equality is not dispatch authority.
7. **Authority ordering:** no provider effect, including writable native startup or incidental lock cleanup, before verified recovery, independent one-shot approval consumption and durable flushed intent. Receipt binds exact T, A, profile, state fingerprint, transaction/recovery digests and operation index. Native startup is not a free read.
8. **Failure prefix safety:** for every failpoint k, only a prefix of approved effects has happened, unrelated projection unchanged, journal records actual durable knowledge, and partial target surfaces remain enumerated. No deletion success from exit0, no NoEffect from exit1/remaining row/finite unchanged scan.
9. **Crash/restart conservation:** before/after each file fsync, directory publication, DB commit and journal event, simulated crash recovery yields the same authenticated knowledge or stricter Unknown. Missing receipt is not failure/success; recovery does not recreate dispatch capability or automatically retry/compensate.
10. **Concurrency serializability or refusal:** any permitted interleaving with target resume, parent-child fork, attachment add, metadata rename, migration, compression, index append or other deletion is equivalent to a valid serial outcome preserving U, otherwise conflict before effect. Advisory-lock acquisition failure/timeouts must be bounded, distinguishable and protected. Do not manufacture serializability from final hashes.
11. **Idempotent observation, not blind retry:** repeated reconciliation changes no provider state and creates no intent/grant. Repeated execute using consumed receipt cannot repeat effects. User-requested retry requires a fresh plan against explicit partial state and new authority; old operation digest alone is insufficient.
12. **Logical success:** positively prove declared target postcondition and retained invariants with coherent coverage, valid exact schema/identity and independently checked stores. If a required read fails or baseline is missing, result Unknown rather than Deleted. UI disappearance or total bytes delta is not sufficient.
13. **Monotone protection:** dropping evidence/adding uncertainty/corruption/more retained dependencies can never turn refusal into eligibility. Adding an unrelated sibling must not change target identity, selected paths or intended write set.
14. **Determinism/privacy:** fixed S yields same typed plan/digest regardless of inventory/row order, harmless unrelated insertion or presentation prose; private transcript body/credentials/unknown raw payload never enters plan/journal/log. Read bounds and cancellation apply to very large records/files.

These are candidate specifications to review. Passing generated tests demonstrates implementation properties within the explicit model; it cannot establish the model's real-provider closure by itself.

## Generated model and repeatable seeds

Propose a state-machine property suite with deterministic seed `0x4d382e3253434f50` (M8.2SCOP) for ordinary CI, minimum4096 generated model cases per selected operation, plus persisted minimized regression seeds. A separate explicitly invoked nightly run may vary seeds and must print exact seed/case/shrink trace. Do not claim4096 as a statistical safety guarantee. Enumerate crash cutpoints and small interleavings exhaustively in addition to random generation; fault scheduling must be deterministic, not sleep-based. No real provider or user root in CI.

Generators should produce:

* Full128-bit IDs, UUID aliases, same-prefix distinct IDs, malformed/duplicate/conflicting descriptors; stable thread plus zero/multiple immutable rollout IDs.
* Active/archived/plain/zstd variants, byte-equal and divergent siblings, selected and superseded revert segments, noncanonical filenames, header mismatch, zero-byte/corrupt/oversized/truncated metadata, duplicate rollout IDs across paths.
* Directed graphs with spawn trees, cycles, orphan raw edges, missing rows, copied forks, history_base references with cutoffs, self-revert lineage, attached children, multi-hop dependencies and unrelated threads sharing cwd/project/name. Generate a retained thread depending on T and T depending on retained U in both directions.
* Logical stores with projection rows keyed by immutable rollout ID (not just T), main metadata/FK cascades/read receipts/tools/attachments, names with repeated target and malformed unrelated entries, logs/queue/goals/memoryv1/v2/message-board rows; unknown tables/schema versions. Each unrelated sentinel has unique content; no “all fixture bytes same” blind spot.
* Filesystem root aliases, nested symlinks, hardlinks/same inode, directory substitution, permissions/owner/device changes, disappearing entries, DB/WAL/SHM states and configurable separate SQLite/log paths. Model identity checks by opened-object metadata as well as pathname.
* Target writer preheld, unrelated writer active, pending reference publication, compressor encode→publish, metadata transaction before/after exclusion, index append during rewrite, two coordinators, cancelled lock wait, crash guard cleanup, lock inode replacement attempts. Label in-process and cross-process locks distinctly.
* ENOSPC/EIO/EACCES/ENOENT/SQLITE_BUSY/SQLITE_BUSY_SNAPSHOT, failed fsync, partial journal publication, failed observer, lost response and process termination at every meaningful durable boundary.

Required oracle: a separate declarative model computes target ownership/retained dependencies/write set and allowed outcome; it must not call the production planner or reuse its SQL predicates/path parser as expected values. Assert noninterference after **every** fault/interleaving prefix, then authenticate transaction state and run read-only reconciliation twice. Include fixed hand-written regression models from the official issues and M8.1 exact native counterexamples. Native positive acceptance tests, once a scoped contract is reviewed, remain opt-in/fresh synthetic exact binary only; generated models never promote production compatibility.

## Review questions blocking a design decision

1. Which precise local postcondition is promised: native view unusable, durable local history removed, hidden from app, full cleanup, or physical reclamation? They require different surfaces. Do not sell one as another.
2. What proves all admitted writers/reference creators are excluded, including paginated metadata operations that do not take target OS writer lock, pending nonattached forks, app/daemon hosts and old versions? A merely private AgentMender lock cannot fence Codex.
3. How are source-owned segments referenced by retained sessions handled while honoring exactly one UUID? Initial refusal is coherent; silently cascading or rewriting retained histories is a scope change.
4. Are configured store roots/FK cascades/host cleanup declared completely for the exact admitted profile? How do unknown schema, missing selected rollout, duplicate canonical IDs and corrupt headers stay visible rather than vanish into a map?
5. Can the same exact postcondition be independently observed after crash without native read-repair or approval reconstruction? If not, success must remain unavailable even if local removals looked correct.

No answers are presumed by this research. M8.1 historical pins/unsupported claims and Claude zero-mutation boundary remain untouched.
