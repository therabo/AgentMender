## Findings relevant to M8.2 design review

1. **Narrow cleanup is a real, common engineering scope.** Tools often claim successful handling of the exact artifacts they recognize,while explicitly retaining memory/history/unknown globals or failing to account for newer stores. AgentMender can learn scope presentation,artifact inventories,unknown residual reporting and recovery UX without inheriting “session absent everywhere” claims.
2. **Native-only and direct-storage are different trust contracts.** Native deletion wrappers avoid inventing database semantics but still need complete preapproved cascading effects and authoritative verification. Direct-storage tools can describe a smaller known set but own identity,write safety,crash recovery,schema compatibility and residual semantics themselves. No implementation examined makes native unknown effects safe by approval alone.
3. **Recovery must preserve unrelated concurrent work.** CSM's recorded-pre/post CAS and conflict refusal is a stronger abstract pattern than replacing entire DB/index backups. Steward's per-DB Backup API is coherent for each DB,not across all stores;automatic full restore does not fence concurrent provider changes. Root's M8 handoff cannot silently become a generic restore engine.
4. **Tool locks are not provider locks.** All observed locks coordinate only the tool or check transient provider locks;app-closed process checks and per-file revalidation do not establish a durable coherent writer exclusion across provider lifecycle. getoverroot's three retries and agf's error-path per-ID retries cannot transfer to AgentMender's no-redispatch Unknown rule.
5. **Logical bytes and disk reclaim must remain separate.** stat.size sums omit sparse/hardlink/APFS clone/SQLite freelist behavior. Backup retention can keep all data and same-volume moves reclaim nothing. getoverroot measures drive free-space delta but it is not isolated causal attribution or erased-byte evidence.
6. **Privacy differs sharply.** Most studied tools intentionally read and back up transcript bodies,raw rows,prompts and global state;Ayo backups include auth.json. AgentMender's existing reconciliation metadata privacy contract cannot be broadened accidentally by adopting their backup strategy. No credentials were read by this research.
7. **Exact version is not a shape guess.** Hardcoded layouts,required-column checks or probing current help/generated schema can be useful observation gates;none alone proves exact installed effect semantics. Existing M8 historical profile and0.166refusal tests must remain unchanged until a separately reviewed new contract is established.

Conclusion: the landscape supplies useful implementation patterns and concrete cautionary counterexamples,not a third-party proof of complete safe0.166session erasure. There is no justification here for broadening mutation,automatically deleting shared/unknown data,claiming full reclaim,or bypassing AgentMender's independent approval,durable intent,fresh validation and protected unknown outcomes. Parent can now evaluate an explicitly scoped M8.2 contract with these distinctions visible.
