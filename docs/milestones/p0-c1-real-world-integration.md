## Implementation and privacy

[ADR-0024](../adr/0024-adaptive-read-only-metadata.md) defines the smaller read
contract. `mcp --session-search` opts into the same thirteen tool names, without a
caller UUID, exact cleanup binary or owned state root. Default stays eight tools;
the separate `--session-removal` mode and its durable preparation keep all prior
requirements. Other removal calls in read mode return
`read_only_removal_unavailable`. Its blocked preview has a typed output alternative
and explicitly incomplete affected scope; it cannot be mistaken for a Ready plan.

The provider worker reuses the opaque evidence directory, source write-denial
attestation, SQLite READ_ONLY/NOFOLLOW, query_only, trusted_schema off, limits and
bounded in-memory Backup API snapshot. It validates the required metadata column
and value contract, not an entire historical schema hash. Additive columns/unknown
producers remain readable. Fixed queries prefer provider display name, return
UUID/project basename/times/archive/available spawn-parent data and exclude
preview/first-user-message/transcripts. Missing or oversized optional labels stay
unavailable. No source DB or transcript copy is persisted in scratch. The recent
inventory is bounded at 500 records/96 KiB; existing MCP response limits remain.
No cwd/project/title proves ownership. `active` here is archive metadata, not a
runtime activity census. Parent/root coverage remains partial.

The installed executable's generated schemas are inspected under real-state
read/write denial in owned scratch. This establishes advertised interface methods,
not a native delete contract. A failed optional probe leaves native availability
Unknown without suppressing otherwise validated metadata. The observed binary
hash in [sanitized evidence](../../compatibility/codex/0.166.0-alpha.6/real-world-readonly/evidence.json)
is audit provenance, not a new metadata admission requirement. No new dependency,
crate, planner, executor, approval store or journal encoding was introduced.

The historical `providers`/scan catalog retains its previous scope; its general
compatibility flag must not be read as the new independent metadata contract.
Future versions can read through compatible columns or a separately evidenced
native read interface. New representations/required column changes fail safely;
universal past/future compatibility is not claimed. Raw local mutation continues
to need exact schema/ownership/concurrency/version evidence. Native effects need
complete preapproval scope and postconditions, regardless of method presence.

## Required human boundary

MCP's public client metadata and the client-side thread-scoped tool API do not
establish an authenticated server-side caller binding here. No model-supplied
`caller_session_id`, environment guess, title, cwd or Active label is accepted as
identity. Keep actual management UUID registration independent before approval,
and revalidate it at planning/dispatch. Future cross-provider host identity remains
separate from the target provider/root.

A terminal challenge/MAC/one-shot DurableIntent still cannot authenticate a person
against a same-user agent with shell/PTY/key control. The real read-only deployment
therefore leaves all destructive admission blocked and has no approval store.
For later acceptance, the human must explicitly select the precise real disposable
UUID, establish the independent operator/model separation, approve an admitted
complete scope and perform the supported operation. Structural proof, other-session
preservation, residuals, logical/physical bytes and optional GUI behavior remain
separate. Stop if those gates are unavailable. Do not start P0-C2 yet.
