## MCP and search

Default MCP still has eight read-only tools. Explicit `mcp --session-removal`
adds five capabilities:

- `session_search`: all-term title/project-basename/UUID metadata matching.
- `preview_removal`: fresh exact primary plan and original digest/fingerprint.
- `prepare_removal`: existing durable transaction/reconciliation preparation,
  requiring the exact reviewed `sha256:` digest.
- `removal_status`: authenticated durable lookup/list across server restart.
- `request_removal_execution`: status and external-terminal handoff, **no dispatch**.

Inputs cannot set roots/binaries, caller identity, approval/principal/clock, SQL,
commands or paths. Confirmation fields are rejected. Preparation alone can write
AgentMender-owned state. MCP has no persistence dependency, approval secret,
receipt constructor, grant/consume/revoke API or provider effect port.

Opt-in results expose provider/root-scoped opaque refs, canonical UUID, title or
reliable UUID fallback label, project basename, Unix creation/activity metadata,
archive state, exact profile/producer eligibility and protected/preview eligibility.
No raw transcript, preview, first-user-message, cwd/root path or raw database is
returned. Labels are untrusted provider data. Null means unavailable. Inventory
bounds (500 records/128 KiB) preserve Partial coverage; oversize MCP responses fail
without silent truncation. Matching is deterministic metadata filtering; natural
language interpretation stays in the calling agent.

Duplicate/similar titles, same-project peers and archives remain separate matches.
No title/cwd grants ownership; an exact root/session is freshly resolved before
planning. Same IDs/titles in another root are distinct. Old process tokens stop
matching after restart; durable IDs recover attempts. No search absence under
Partial coverage is a deletion proof.

`--protect-codex-session`. A real host/human must verify which UUID is the actual
management chat; MCP metadata supplies no authenticated binding. The selected

even if flags are omitted. New protections invalidate old plans, and immediate

The terminal broker and authenticated one-shot grant machinery are reused. Review
shows the exact original provider/root/session/profile/affected set, retained
protections, irreversible payload effects, residuals and lack of payload recovery.
Human approval **and execution** remain external. MCP execution requests return
status even with a grant, without consuming it. A model boolean/PTY completion
cannot become independent human authorization.

This development agent has unrestricted same-user shell/PTY/store access. The
terminal/key design does not authenticate a person against that adversary. Manual
independent operation is a deployment assumption, not OS-enforced separation.
No actual human approval or authenticated caller binding is claimed from tests.
[ADR-0023](../adr/0023-conversational-primary-removal-handoff.md) records this
consequential boundary; ADR-0022 and historical ADR/report bodies are preserved.

## Recovery, retries and collateral evidence

Identical preparation retries recover the existing attempt, without resetting or
renewing authority. Client disconnects can recover via `removal_status({})`; server
restart needs no old opaque ref. An incomplete preparation is inspection knowledge,
not dispatch permission. Denied/expired/revoked/forged grants cannot execute;
consumed attempts cannot execute twice. Identical expired/revoked attempts are not
automatically renewed by MCP: a fresh independently reviewed attempt is required.

Existing durable intent-before-effects, poisoned divergence, crash/reopen and
read-only reconciliation behavior is retained. A crash before dispatch but after
intent, lost response after effects or unknown outcome never triggers another
operation, compensation or whole-store restoration. Recovery metadata is not a
payload backup. New references/dependencies require new preview/review, never scope
expansion. Default active-writer and hidden-native-descendant guards still run.

Disposable component tests cover T, registered M, same-cwd/project/duplicate-title
peers, similar UUIDs, archives, missing titles, producer mismatch and transcript
privacy. Same-title/ID other-root, Partial coverage, unregistered caller and
cross-provider references are negative selection tests. After preparation, adding
T to protection refuses dispatch and leaves the prepared grant unconsumed. A valid
fixture grant then removes only T; every retained sentinel remains intact.

A real subprocess stdio test uses the exact stable profile and protected worker:
search/disambiguation → preview → prepare/retry → external handoff → explicit
**fixture grant** → separate production CLI effect → independent structural
verification → MCP restart/status → stale ref and repeated execution refusal.
It verifies M, a same-title/same-cwd peer and a complete other-root inventory remain
byte-intact. The final source passed this test in 57.39 seconds after a local disk-full condition
was resolved by Cargo cleaning generated development artifacts. An earlier run coincided with disk exhaustion and returned Failed without a
verified-removal claim; it is not counted as successful acceptance.
